2)TradeOffs : WHy hash map and dll 
Hash map provides average O(1)key lookups but doesnt maintains the order of usage or identify least recently used.
A doubly linked list maintains a usage order and allows nodes to be removed or added at O(1) when its pointer is available i.e in this case in map and for which map takes O(C) space for storing each node
Combining these two :
On a cache hit the node can be located and moved from one place to another effectively
and on caches full, least recently used entry can be removed from tail and hash map.

Trade off is additional memory usage of map and node pointers to maintain order and provide address of each node in O(1)

I would maintain two min heaps : 
1)Busy_rooms: min heap ordered by meeting end time storing each rooms's time and room id 
2) Available_rooms: a min heap containg the identifier of rooms that are currently free

4)Concurrency:Making the LRU cache thread safe
Current doubly lined list and map is not thread safe becuase multiple threads can modify the map and doubly linked simultaneously.
To make thread safe : Introdce mutex to protect incorrect cache results
Get() ops would acquirwe lock before checking map and moving a node to front.It would release lock after retrieving value and completing list updates
Put() ops : acquire lock before checking/updating map or inserting node or evictions. Release only when after all related updates are complete
I would use std::lock_guard<std::mutex> to ensure lock is released including when exception occurs. also std::lock_guard<std::mutex automatically release the lock when guard goes out of scope.
We can use a single mutex also because hash map and linked list form one shared state that must remain consistent.
